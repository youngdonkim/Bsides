이 가이드는 SKILL.md가 사이클 관련 작업(새 시작·디렉토리 구조 확인·라벨 결정·엣지 케이스 처리)이 필요할 때 읽는다. 명확한 케이스만 자동 진행하고, 모호한 케이스는 한 번 확인 후 진행.

## 1. 명시적 트리거 (즉시 새 사이클 시작)

다음 표현이 나오면 사용자 추가 확인 없이 §5 새 사이클 시작 절차로 진입한다.

- "MVP 사이클 시작해줘"
- "v2-mvp 시작"
- "v3-production 시작"
- "다음 사이클 가자, 이번엔 MVP"
- "production 사이클로 넘어가자"
- "프로토타입 사이클 닫고 MVP 사이클 시작"
- "새 사이클 시작" / "다음 사이클 시작"

**판별 기준**: "사이클" 또는 "vN" 형태가 명시적으로 있고, 시작·넘어감·전환 의미의 동사가 함께 있음.

## 2. 모호한 트리거 (한 번 확인 후 진행)

다음 표현은 두 가지 해석 가능. 자동 사이클 전환 금지.

- "이제 MVP 만들고 싶어"
- "MVP 작업 시작하자"
- "MVP로 넘어가자"
- "프로토타입 끝났으니 MVP 가자"
- "MVP 만들자"

**왜 모호한가**:
- (a) 새 사이클 v2-mvp 시작 — 폴더 새로 만들고 직전 산출물 base로 복사
- (b) 현재 사이클(v1-prototype) 안에서 MVP 기능 구현 — 폴더 변화 없음

### 확인 질문 템플릿

다음 형식으로 한 번 묻는다 (라벨은 실제 값으로 치환). 톤은 SKILL.md §1.3대로 반말·친근·짧게.

```
v1-prototype 닫고 v2-mvp 사이클 새로 시작할까, 아니면 v1 안에서 MVP 작업 추가하는 거야?

- 새 사이클 시작: v2-mvp 폴더 만들고 v1 산출물 base로 복사. Intent부터 회고 기반으로 다시 점검.
- 현재 사이클 안 작업: 폴더 그대로. 어느 단계 작업인지만 알려줘.
```

## 3. 비트리거 (현재 사이클 안 일반 작업)

다음 표현은 사이클 전환이 아니다. 현재 사이클 안 일반 작업으로 처리.

- "MVP에 들어갈 결제 기능 추가해줘"
- "이 부분 MVP 단계 고려해서 다시 짜줘"
- "MVP 우선순위로 PRD 다시 보자"
- "이거 production 가능한 수준으로 리팩터링해줘"

**판별 기준**: MVP·production 같은 단어가 있지만 (a) 단계 전환의 동사가 없거나, (b) 구체적 기능·작업 대상이 함께 명시됨.

## 4. 라벨 (컨벤션 + 추론 규칙)

### 4.1 컨벤션

- `v1-prototype` (기본 첫 사이클)
- `v2-mvp`
- `v3-production`
- 그 외 사용자가 명시: `v2-beta`, `v3-launch`, `v4-v2-major` 등.

### 4.2 추론 규칙

명시적 트리거에서 라벨이 안 명시된 경우(예: "다음 사이클 시작"):

1. **현재 vN 보고 다음 기본 라벨로 매핑.**
   - v1-prototype → v2-mvp
   - v2-mvp → v3-production
   - v3-production 이후 → 사용자에게 라벨 명시 요청 (`v4-{label}` 형태)
2. 사용자가 다른 라벨 명시하면 그 라벨 사용.
3. **라벨이 결정되면 폴더 생성 직전 1회 confirm.** "v{N}-{label} 사이클 새로 시작할게. 가도 돼?" — 폴더 생성 후 되돌리기 부담이 있어 한 번 확인.

## 5. 새 사이클 시작 절차

새 사이클 시작 의도 확정 후 다음 순서로 진행:

1. 직전 사이클의 `retro.md` 읽고 핵심 포인트(개선 항목·검증 결과·다음 사이클 입력) 추출.
2. §4 절차로 새 라벨 결정.
3. 새 폴더 `cycles/v{N}-{label}/` 생성.
4. 직전 사이클의 모든 `.md` 산출물을 새 폴더로 복사 (코드·`tasks/`는 복사 안 함). 새 폴더의 vN이 가장 크므로 자동으로 진행 중 사이클로 인식됨.
5. Intent 단계부터 시작. 단, 빈 파일에서 시작 안 함 — 복사된 `intent.md`를 base로 두고 "이번 사이클에서 무엇이 달라지는지"를 회고 기반으로 사용자와 논의하며 **diff 형태로 업데이트**.
6. 이후 단계도 모두 "기존 산출물 업데이트" 형태로 진행. 덮어쓰기가 아니라 추가·수정·삭제 의식.

## 6. 디렉토리 구조

```
planning/
├── cycles/
│   ├── v1-prototype/
│   │   ├── intent.md
│   │   ├── sketch.md (또는 sketch/)
│   │   ├── prd.md
│   │   ├── architecture.md
│   │   ├── data-model.md
│   │   ├── tasks/
│   │   ├── qa-report.md
│   │   ├── deploy-checklist.md
│   │   └── retro.md
│   ├── v2-mvp/        ← v1 산출물 base로 업데이트
│   └── v3-production/
└── docs/             ← 사이클 무관 문서(BRAND·MANIFESTO 등) 선택
```

영구 의사결정(ADR)은 `planning/adr.md` 단일 파일. 사람용 docs는 `docs/`. **이 스킬은 `cycles/` 외 폴더에 손대지 않는다.**

## 7. 엣지 케이스

### 7.1 사용자가 cycles/ 디렉토리를 수동으로 만든 상태에서 첫 호출

`cycles/v1-prototype/`이 이미 있고 안이 비어있는 경우, 새 프로젝트로 간주하지 않고 "v1-prototype 사이클 발견. Intent부터 갈게." 한 줄 안내 후 진행.

### 7.2 사용자가 vN을 건너뛰고 싶다고 할 때

예: v1-prototype에서 바로 v3-production으로 점프. **허용하되 한 번 확인.**

- "v2 건너뛰고 v3-production으로 가는 거 맞아? 보통은 v1 → v2 → v3 순서인데, 의도 있으면 갈게."
- 사용자 확정 시 v2 폴더 생성 안 함, v3-production 폴더만 생성.

### 7.3 동일 vN 라벨 충돌

이미 `v2-mvp/` 폴더가 있는데 사용자가 "v2-mvp 시작" 요청. 둘 중 하나로 처리:

- **이어 작업** (디폴트): 기존 폴더가 진행 중이면 그 안에서 단계 판별 후 진행.
- **새로 시작**: 사용자가 명시적으로 "v2-mvp 처음부터 다시"라고 하면, 기존 폴더를 `v2-mvp.archived-{timestamp}/`로 이동 후 새로 생성. **destructive operation이라 사용자에게 반드시 1회 확인** ("기존 v2-mvp 폴더를 archive로 옮기고 새로 시작할게. 진짜 OK?").
