# 사용자 플로우

외부 잠재 객원 멤버(intent.md B-2) 단일 플로우. 기존 멤버는 카톡으로 운영되어 홈페이지 사용 거의 없음 → 별도 플로우 없음.

```
[지인 소개 / 검색 / 외부 링크 공유]
       ↓
   1. 홈페이지 랜딩 (메인)
       ↓
   2. 첫 5분: Bsides가 뭔지 · 운영방식 (한 사이클, 한 멤버, 서비스 출시) · 객원 → 정식 전환 흐름 파악
       ↓
   3. 검토: 현재 릴레이 멘토 / 진행상황 정적 페이지(강의 콘텐츠 누적) /
            과거 출시 사례 / 운영자 정보
       ↓
   [선택 — 재방문 1~2회: 새 업데이트 확인]
       ↓
   4. "객원 멤버 신청" 클릭 → 메인 하단 신청 섹션 또는 카톡 채널 안내 노출
       ↓
   5. 카톡으로 자기소개·신청 동기 전송
       ↓
   6. 운영자 카톡 응답 → 워크샵 일정·합류 안내
       ↓
   [홈페이지 밖 — 화상/오프라인 워크샵 합류]
```

운영자 콘텐츠 추가(녹음·메모 → LLM 가공 → AI 이미지 → 정적 페이지)는 **코드 작업 / 파일 추가 → git push** 흐름. product UI 아니므로 Sketch 범위 밖.

# 핵심 시나리오

## S1. 첫 방문 → 5분 이해 (H2 funnel)

사이드 잡 지망 30대 직장인으로서, 지인 소개로 들어온 Bsides 홈페이지에서 **5분 안에** "여기가 뭐고 누구를 위한 곳인지·내가 객원 자격이 있는지"를 파악하고 싶다.

- **트리거**: 외부 링크 클릭 → 메인 페이지 진입
- **기대결과**: "한 줄로 뭐 하는 곳"인지 즉시 이해 + 다음 행동(검토·신청·이탈) 판단

## S2. 현재 워크샵 검토 (H3 시그널)

출시 의지 있는 30대 프리랜서 디자이너로서, **현재 진행 중인 릴레이 멘토의 워크샵 정보·진행상황 페이지·과거 출시 사례**를 검토해서 객원 멤버 신청 가치를 판단하고 싶다.

- **트리거**: 메인에서 "현재 워크샵" 또는 "진행상황" 메뉴 클릭
- **기대결과**: 진행 콘텐츠 누적 정도·멘토 신뢰도 형성 → 신청 의지 결정

## S3. 카톡으로 객원 멤버 신청 (H2 funnel 종료)

검토를 마친 잠재 객원으로서, **복잡한 가입 절차 없이** 카톡으로 운영자(현지)에게 자기소개·신청 동기를 바로 전달하고 싶다.

- **트리거**: "객원 멤버 신청하기" 버튼 클릭
- **기대결과**: 카톡 채널 안내(`open.kakao.com/o/bsides`) 노출 → 클릭 한 번에 카톡 진입 → 메시지 전송 완료
- **fallback**: 카톡이 어려우면 hi@bsides.kr 이메일

## S5. 객원 → 정식 멤버 전환 (H1 자생 검증의 핵심 경로)

객원 멤버로 한 사이클 참여한 사람으로서, **단계 명확한 절차로 정식 멤버로 전환**되어 다음 사이클의 주인공 후보가 되고 싶다.

- **트리거**: 한 사이클 종료 후 운영자·기존 멤버의 권유
- **기대결과**: 4단계 흐름 — **객원 참여 → 운영자·멤버 심사 → 약관 동의 → 정식 멤버** — 통과 후 정식 멤버 자격. 다음 사이클 주인공 자격 획득.
- **노트**: 객원 참여 없이 바로 정식 합류는 없음. H1 자생 메커니즘의 사회적 검증 layer.

## S4. 재방문 → 최종 결정 (H2 신뢰 형성)

1차 검토 후 결정을 미룬 객원 후보로서, 1~2회 재방문해서 **새로 추가된 진행상황·강의 콘텐츠**를 확인하고 최종 결정하고 싶다.

- **트리거**: 며칠 뒤 재방문 (북마크 / 검색)
- **기대결과**: 진행상황 페이지 업데이트 확인 → 이번 회차에 신청할지 / 다음 회차를 기다릴지 결정
